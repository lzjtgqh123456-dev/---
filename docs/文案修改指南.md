## 二、怎么快速找到某一句话

在项目根目录执行（把「要改的话」换成你看到的那句）：

```bash
cd /d/ai/projects/study-assistant
grep -rn "要改的那句话" app/src/main/java app/src/main/res
```

输出里 `文件名:行号` 就是你要改的位置。例如：

```bash
grep -rn "图片翻译（离线 OCR）" app/src/main/java
# → feature/translate/TranslateScreen.kt:262:  Text("图片翻译（离线 OCR）", …)
```

**注意**：文案里可能带标点或换行，搜短一点的关键词（比如 `离线 OCR`）更容易命中。
也可以直接把那句话发我，我告诉你文件:行号，或者直接帮你改。

## 四、安全边界：这些别改

| 别改 | 在哪 | 为什么 |
|---|---|---|
| `VaultCategory` 的 `key`（`"passport"` 等） | `domain/VaultCategory.kt` | **已存进数据库**，改了老记录会变"其他"；改 `label` 才是显示名 |
| xlsx 里读的表头/关键字（`Описание`、`Пр.`、`Вторник`…） | `feature/study/ScheduleMatrix.kt` | 那是**解析俄文课表用的匹配规则**，不是界面文案 |
| `SharedPreferences` 的 key（`"ai_presets"`、`"custom"`、`"classFilter"`…） | 各 Repository/ViewModel | 改了会读不到用户已存的数据 |
| 正则、URL、模型文件名（`det.onnx`、`pcfg…`） | 各 data 层 | 属于逻辑，不是文案 |
| `"\\n"` 之类的转义 | Kotlin 字符串 | 写错会编译报错；要换行就写 `\\n`（或 `System.lineSeparator()`） |

> 简单判据：**只改"引号里、给人看的字"**；带 `key`/`id`/URL/文件名的别动。

## 五、如果你想"一个文件改全部文案"

可以把文案全部抽成 Android 字符串资源（`res/values/strings.xml`），之后你就只改这一个文件。
可行性：
- 好处：一处修改；还能顺手做多语言（`values-ru/strings.xml` 等）。
- 代价：约 1194 条要逐个替换成 `stringResource(R.string.xxx)`，属于**机械但量大**的重构；
  建议**按页面分批**做（一次一个 feature，改完立即编译+装机自测），不要一次全改。
- 推荐顺序（按你最常改的）：`feature/translate` → `feature/net` → `feature/files` → `feature/study`。

要开始就说「把 XX 页面的文案抽成资源」，我会：
1. 只动那一个页面的文案 → `strings.xml`；
2. 保留所有逻辑与 key；
3. 编译通过后装机，把改动前后的文案列给你核对。
